# 对话页升级方案：快捷入口 + 报告卡片

> 状态：决策已定（见 §5），开发中。分支 `feat/chat-ui-upgrade`。
> 设计稿：「利智研小程序 – Ai助手UI」，Figma：<https://www.figma.com/design/bJ2JMCfMmK7qb5jqJDusVM/>（利智研小程序-前端）。

## 0. 目标

现在的 `static/index.html` 只有「消息列表 + 输入框」。升级分两期：

| 期 | 做什么 | 解决什么 | 估时 |
|----|--------|----------|------|
| 一期 | 快捷入口：欢迎页、您可以这样问我、分类标签栏、底部抽屉、关键词联想、回答排版；管理后台可编辑 | 新用户不知道能问什么；常用问题要手打；长回答难读 | 6.5 天 |
| 二期 | 报告卡片：长分析以卡片出现在对话里，点开是独立面板，可导出、可分享、有版本 | 长报告挤在气泡里难读；表格/图表/导出/分享没有统一载体 | 9.5 天 |

两期互不依赖，一期可以先上线。

**不做**：任意 HTML 报告（见 §5 决策 1）、跨会话的报告库、报告协同编辑。

### 2.2 内容走配置，管理后台可改

### 2.3 管理后台编辑

`static/admin.html` 加一个「快捷入口」页签，接口挂在 `router_admin.py`（`require_admin`）：

| 接口 | 作用 |
|------|------|
| `GET /api/admin/quick-entries` | 当前生效内容 + 来源（默认 / 线上）+ 最近 5 个历史版本的时间与操作人 |
| `PUT /api/admin/quick-entries` | 整份保存；服务端校验后写 JSON，旧版本留档 |
| `POST /api/admin/quick-entries/rollback` | 回到某个历史版本 |
| `DELETE /api/admin/quick-entries` | 删除线上值，退回仓库默认 |

- 编辑界面两块：「欢迎问题组」（组 → 问题）和「分类」（分类 → 能力胶囊 → 关键词 / 问题），可增删、上下移动；右侧按 375px 宽实时预览
- 校验上限：欢迎问题组 ≤ 6、分类 ≤ 8、每类胶囊 ≤ 8、每个胶囊问题 ≤ 20、问题 ≤ 60 字；`XXX` 占位每题最多 1 个
- 历史只留最近 5 版，用来回退误操作
- 每次保存、回退、删除写安全审计（`data/audit/security-*.jsonl`），与改悬浮图标一致

### 2.4 关键词联想

Figma 标注「问题关键词联想，提供 3–5 条候选」。原方案里的「最近问题」设计稿没有，**不做**。

流程：用户输入「易方达策略成长混合」→ 识别出这是一只基金 → 拿 `entity: fund` 那几类里带 `XXX` 的问题，把 `XXX` 换成这个名称 → 显示 3–5 条，名称部分用主色高亮。

| 部分 | 做法 |
|------|------|
| 接口 | `GET /api/chat/suggest?q=<输入>`，需鉴权；输入 ≥ 2 个字才查，前端 300ms 防抖 |
| 名称识别 | 只读 `fund-research-db` 的 SQLite：基金简称 / 6 位代码、基金经理、基金管理人（简称 / 全称）、私募管理人 / 产品简称。规则：完整名称 > 名称开头（还没打完）> 输入里包含的最长名称 |
| 候选问题 | 从快捷入口配置里取该实体类型的 `XXX` 问题，按配置顺序取前 5 条；后续可按点击率排序 |
| 没识别出名称 | 不浮层，不打扰 |
| 名称索引 | `admin/name_index.py`：首次请求从 SQLite 读一次放内存；每次请求比对库文件修改时间，管理后台发布新库后自动重建 |

前提：部署环境里有构建好的查询库（`skills/fund-research-db/data/fund_research.sqlite3`）。没有时接口返回空，前端不显示联想。

## 3. 二期：报告卡片

### 3.1 用户看到什么

> **设计缺口**：Figma 里没有报告卡片和报告面板——设计稿的长回答是直接排在对话里的（§2.7）。已定由开发按 §2.6 的字号、颜色自行设计实现，面板内排版沿用 §2.7，做完再请设计走查。

1. Agent 产出长分析时，对话里出现一张卡片：标题 + 内容缩略（结论条 + 第一张图；没有图就核心观点 / 第一张表）+ 「查看完整报告」。面板右上角只有一个「导出」菜单：PDF / Excel（有表格才有）/ 复制文本
2. 点开：手机全屏面板，宽屏（≥960px）右侧面板，对话还能继续
3. 面板里：结论条、指标卡、核心观点、编号章节、表格（涨红跌绿、记分卡标最优）、图表、风险提示、数据来源；右上角「导出」菜单（分享 M9 加进同一菜单）
4. 用户说「把第二只换成 XXX」，Agent 在**同一份报告**上出 v2，卡片显示「已更新 v2」，面板可切回旧版本

### 3.2 报告格式：固定研报骨架

模型交出的是数据，不是 HTML。骨架由我们固定，模型只填内容，样式和编号都由渲染器负责：

```json
{
  "report_id": "rpt_8f3a",
  "version": 2,
  "title": "易方达蓝筹精选 vs 景顺长城新兴成长",
  "summary": "两只都偏消费，蓝筹回撤控制更好",
  "as_of": "2026-10-28",
  "key_points": ["蓝筹近一年回撤 -11%，比新兴成长少 8 个点", "…"],
  "sections": [
    {"title": "核心指标", "blocks": [
      {"type": "markdown", "text": "…"},
      {"type": "table", "title": "核心指标对比", "columns": ["指标", "A", "B"],
       "rows": [["近一年", "-3.2%", "1.5%"]], "signed_columns": ["A", "B"], "source": "利得基金研究数据库"}
    ]},
    {"title": "净值走势", "blocks": [
      {"type": "chart", "chart": "line", "title": "近一年净值", "unit": "净值", "x": ["2025-01", "…"],
       "series": [{"name": "A", "data": [1.0, 1.02]}], "source": "…"},
      {"type": "conclusion", "text": "…"}
    ]}
  ],
  "risk_note": "本报告样本仅 6 个月",
  "sources": ["利得基金研究数据库 2026-10-28"]
}
```

成品的固定顺序（面板与 PDF 一致）。读者分三层读：5 秒看报告头知道答案，30 秒看核心观点 / 记分卡 / 主图知道为什么，最后才读正文。

1. 封面：「研究报告」+ 标题 + 摘要 + 数据截至 · 版本 · 生成时间
2. 结论条 `verdict`：一句话直接回答问题；指标卡 `kpis`：2–4 个大数字（`label` / `value` / `note`，`tone` 默认按正负涨红跌绿，非收益类写 `neutral`）
3. 核心观点：2–5 条 `{text, tone}`，`tone` 标「优势 / 权衡 / 风险 / 建议」，`info` 不标；旧报告的纯文字观点照常显示
3. 目录：≥4 个章节时出现（三章一屏看完，目录只占地方），面板里可点击跳转
4. 章节：自动编「一、二、三」，模型写标题时不带序号；`lead` 是本节结论，加粗显示在标题下；表、图分别全局编号「表 1 / 图 1」，标题下方写「资料来源：…」；`conclusion` 显示为「小结」。每章的写法固定为「一句 `lead` + 一个图表或模块 + 最多 3 个论点」，正文 ≤200 字
5. 风险提示：本报告的 `risk_note` + 形态配置里的通用免责（`tool_pack_overrides.report.config.risk_note`）
6. 数据来源

- PDF 用 `@page` 页边盒：左上报告标题、左下页脚（形态配置 `footer`，research 为「内部资料 注意保密」）、右下「第 n / N 页」；表格跨页时表头重复，「资料来源」不与表格分页
- Excel 的 sheet 名跟随表格编号「表1 标题」，「说明」页带数据截至和核心观点
- 旧格式（只有 `blocks`）照常能读：当作一个无标题章节渲染；`update_report` 一旦给了 `sections` 就丢掉旧 `blocks`
- `markdown` 用内置小转换器；`signed_columns` 列按正负着色（红涨绿跌）
- 记分卡：`table` 带 `row_best`（行是指标，每行 max / min / null）或 `col_best`（行是对象，{列: max|min}），服务端算出最优格（并列都标），面板经接口的 `highlights` 拿到，PDF 直接标
- 按问题选图（写进提示词）：对比 → 记分卡 + `scatter` 风险-收益散点（风险写正数，越靠左上越优）；排序 / Top N → `rank` 横向排名条（自动从大到小、正负分色，≤30 项）；走势 → `line`；占比 → `pie`
- `chart` 支持 line / bar / pie / rank / scatter / percentile / contrib，**服务端画成 SVG**（`reports/render.py`），面板直接嵌、PDF 原样打印，两边用同一份。画布按手机宽度设计（400 宽），PDF 里限宽 520px
- 图表样式：扁平、低饱和配色（相邻色明度接近、色相拉开），圆点图例，折线不画常驻圆点、单条线带浅色面积，饼图画成环形
- 图表交互：SVG 里带透明感应区（折线 / 柱状每个 x 一块、排名条每行一块、散点每个点一圈 `c-hit`，饼图每个扇区 `c-slice`）、一条隐藏的辅助竖线和每个 x 一组隐藏圆点。面板里悬停或点按显示数值浮层（饼图带占比），折线点亮该处圆点，柱状 / 饼图其余部分变淡，点空白或滚动收起；PDF 里感应区透明，不影响打印
- 积木在服务端做 schema 校验，不合法直接把错误还给模型重试；`publish_report` 缺 `key_points` / `sections` 直接拒绝
- 篇幅检查（`report_pack._BREVITY`）：verdict / 观点 / 指标卡注释 / lead 超长，或正文有段落 >160 字、一章正文 >500 字，退回让模型压短，不落盘

**排版层**（渲染器做，所有报告都生效，含旧报告）：

- 正文行高 26px、段距加大、正文色比标题浅一档，表格和指标卡的数字等宽
- 论点块：「**一句论点。** 展开的话」这种粗体开头的段落，论点单独一行（15px 粗体）、展开的话在下面（浅色），左侧一条细线；展开不到 8 个字的不拆
- 数字：`73.0` 显示 73，五位数以上加千分位（18,894）；文字里五位数以上的「亿」换成「万亿」（18894.0 亿 → 1.89 万亿）。PDF（`render.tidy_text` / `display_cell`）与面板（`tidyText` / `cellText`）同一口径
- 柱状图类目 >6 个、标签长到写不下或柱子 >16 根时自动改横向；0 值的柱子也留一道看得见的细条

**通用模块**（按功能，不按某一类报告；不编号，放在章节里）：

| 积木 | 用途 | 数据 | 显示 |
|---|---|---|---|
| `entities` 对象卡 | 介绍或比较对象 | `items=[{name, kind, tags≤4, note}]`，`metrics=[{label, values, best}]` | 1 个 = 画像卡（名字、类型、标签、一句话画像、关键数）；2 个 = 对决卡（VS、逐项镜像条、赢家高亮、「甲 胜 1 项 · 持平 1 · 乙 胜 3 项」）；3–5 个 = 并排卡（横向表格，最优格高亮，底部「胜出项」） |
| `chart: percentile` 分位条 | 在同类里排第几 | `x` 指标名，`data` 同类前 x%，`display` 原始值，`x_label` 同类口径 | 一行一项，左差右好，圆点 + 同类中位虚线，右侧「前 12% / 后 30%」 |
| `chart: contrib` 贡献条 | 占多少、贡献多少 | 两个系列：占比（灰）、贡献（主色，有负数时按涨红跌绿） | 每项两条横条 |
| `fit` 适合 / 不适合 | 给建议 | `good` / `bad` 各 ≤5 条，标签可改 | 绿 / 红两栏 |

- 记分卡（`row_best` / `col_best` 的表）和对象卡下面自动加「胜出项：甲 1 · 乙 2（持平 1）」；胜出格和项数都由服务端算（`render.best_cells` / `tally`），面板经接口的 `highlights` / `tallies` 拿到
- 卡片缩略图：两个及以上对象的报告优先放对决 / 并排卡（前 3 项指标），没有才放第一张图
- 按报告类型搭模块（写进提示词）：单只 / 经理画像 = 对象卡 + 分位条 + 走势 + 适合 / 不适合；两个对象对比 = 对决卡 + 记分卡 + 适合 / 不适合；三个及以上 = 并排卡 + 散点 + 记分卡；排序筛选 = 指标卡 + 排名条 + 明细表；组合归因 = 贡献条 + 环形；复盘 = 走势 + 记分卡（对比基准）

### 3.4 分享

功能和登录校验都做，登录校验先不强制，用开关控制：

| | `REPORT_SHARE_REQUIRE_LOGIN=false`（默认） | `=true` |
|---|---|---|
| 谁能看 | 拿到链接的人 | 拿到链接、且有宿主登录态的人 |
| 链接 | 只读，签名方式同下载授权（`issue_download_grant` 已支持 `ttl_seconds`），7 天过期 | 同左 |
| 看到什么 | 分享那一刻的版本，不随后续更新变化 | 同左 |

- 分享链接打开的是只读页（`/r/<token>`）：只有报告本体，没有对话、没有输入框
- 发起分享的人可以撤销：撤销后链接立刻失效。签名令牌本身无状态撤不回，所以每次分享在服务端记一条分享记录（令牌 id、报告 id、版本、分享人、是否撤销），打开时验签之后再查这条记录
- 每次创建分享、每次打开、每次撤销都写安全审计，记录报告 id、分享人、打开人（未登录时记 IP）
- 开关打开后，未登录的人打开链接会看到「请从主产品登录后查看」，与首页闸门一致

### 3.5 什么时候出报告（提示词）

写进 `configs/profiles/research/agent.md` 和 `fund-research-db` 的「交付方式」一节：

- 出报告：用户要「报告 / 分析 / 对比」，或答案有 ≥2 个章节，或有 ≥10 行的表
- 不出报告：单个数字、口径解释、一两句话能答完的
- 出了报告，对话正文只写 1 句结论，不重复报告内容

这条要在灰度时看实际触发率再调。

### 3.6 前端

- `assets/chat/report.js`：卡片组件（标题 / 版本角标 / 内容缩略图，缩略图进入视口才取）、面板（全屏 / 侧栏两种布局）、积木渲染器、版本切换、导出、复制
