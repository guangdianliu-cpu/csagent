# 当前实现说明

代码地图 + 契约 + 约束。改这个仓库前先读本文。

---

## 0. 定位

单 Agent + 全工具 + Skill 注入的智能体服务：一条 ReAct 循环挂载全部工具，
通过 Skill 文档（Markdown）而非改代码扩展业务能力，多通道（HTTP / 企业微信）接入。

一个进程只有一个 Agent、一份系统提示词、一份 `configs/agent.yaml` 的 `tool_packs` 列表。
没有模式切换、没有环境变量选身份。能力范围不同的部署靠改这个列表区分。

## 2. 请求链路

```
入站（HTTP SSE / 企微长连接 / 微信群：发送机推到 /api/wechat/link/messages）
  -> MessageGateway.handle_message()          # @提及剥离、附件->文本、全局 inflight 限流
      -> Agent.handle_message_stream()        # 进程内只有一个实例
          |- InputGuard 输入护栏
          |- 记忆加载：short_term / snapshot_store / load_tool_calls / 回复偏好
          |- ContextBudgetAllocator.allocate  # 分层 Token 预算
          |- StructuredCompactor.build_context  # Checkpoint 块 + 最近对话原文块
          |- QueryAwareContextSelector         # 按 query 裁剪快照与工具流水
          |- PromptLayoutOptimizer             # 稳定前缀，提升 KV Cache 命中
          |- SkillDiscovery.render_index()     # L1 索引常驻 system prompt（{{skill_index}}）
          |- Agent._run_react(DomainTaskRequest)
          |     |- build_system_prompt()       # 渲染 configs/profiles/<形态>/agent.md
          |     -- ReactLoop.run(...)
          |           循环: LLM(function calling) -> ToolRegistry.execute -> 结果回灌
          |                 （结果先过 result_filter 遮掉已知密钥值，再进上下文）
          |           -> 模型调 list_skills / load_skill 按需取 Skill 正文
          |           -> 模型调 __final_answer__ 时切流式输出（on_delta）
          |              正文与思考过程的每个片段先过 OutputGuard.stream() 脱敏 / 拦截再出站
          |- OutputGuard 全文复判（落库与审计用；已流出的内容不重发）
          |- 记忆回写（short_term / transcript / Checkpoint 后台刷新 / 工具快照）
          -- SessionAuditLogger 落 JSONL
      -> 出站（SSE 事件 / 企微增量消息 + outbound_files 文件队列 / 微信群：进发件箱等发送机来取）
```

微信群通道（`wechat/bridge.py`）的几条规矩：

- 会话 = 群：`session_id = wechat:group:{群备注名}`，整群共用记忆和工作区；发言人昵称放 `metadata.speaker`，
  由 MessageGateway 在正文和对话记录开头标成 `[群成员 {昵称}]`。principal 的 `auth_method=wechat`、`user_id` 仍是提问人。
- 本服务是服务端，发送机凭 `WECHAT_LINK_TOKEN` 主动连上来（`hub.py`）。挂 `/api/wechat/link/*`：
  `hello`（发送机问从哪条推，返回游标和 `session`）、`messages`（推消息，原图随消息上传）、`outbox`（长轮询取回复）、
  `outbox/{job}/files/{n}`、`outbox/{job}/result`。回复任务只在内存里，交出去 180 秒没回报再交一次，15 分钟没发出去作废。
  本服务重启后 `session` 变了，发送机会重新 hello、从落盘的游标补推。
- 引用的截图作为图片附件进 Gateway（存到会话 `inbound/`）；引用的文字走 `quote_text`。
- 发送机标了 `warnings`（`first_read` 除外）的、读到超过 `max_age_minutes` 的、超过每群限速的，不跑 Agent。
- 回复是纯文字（Markdown 去标记）开头写「@提问人」；Agent 的 `send_file` 文件作为同一次发送的附件。
  `request_id = wechat-at-{库标识前 8 位}-{消息id}-reply`（「已收到」是 `-ack`），重复处理也只发一次（发送机把结果落盘去重）。
- 游标属于发送机的某个消息库（`inbox` 标识），只在一条消息处理完后前进（多条并行时等前面的做完），落盘
  `data/wechat/cursor.json`。库变了（发送机删库重建、换了一台）按 `start_from` 重新开始，旧库没处理完的不再挪游标。
- 确认卡片在微信里没法点：出了卡片只在回复末尾说明「需要人工确认」，卡片照常登记、过期作废。

## 3. 关键契约

```python
# tools/base.py —— 新增工具的唯一入口
class BaseTool(ABC):
    name: str
    description: str

    @property
    def parameters_schema(self) -> dict[str, Any]: ...   # 默认宽松 schema；有结构化参数的工具应覆盖

    async def execute(self, arguments: dict[str, Any], scope: CustomerScope) -> str: ...

class ToolPack(ABC):
    pack_name: str
    description: str
    def initialize(self, config: dict[str, Any]) -> None: ...
    def get_tools(self) -> list[BaseTool]: ...
    async def shutdown(self) -> None: ...
    # 可选：async def connect(self) -> None   # 需要动态发现时（见 mcp_pack）

# tools/registry.py
ToolRegistry.from_tools_and_agent(tools: list[BaseTool], agent_name: str) -> ToolRegistry
ToolRegistry.list_tools_for_agent(agent_name: str) -> list[BaseTool]
ToolRegistry.list_tool_schemas_for_agent(agent_name: str) -> list[dict]   # OpenAI tools 参数格式
await ToolRegistry.execute(tool_name, arguments, scope, agent_name) -> str

# agent.py
Agent.build_system_prompt() -> str

Agent.load_history(session_id: str, limit: int | None = None) -> list[ChatMessage]
#   只读；GET /api/chat/history 靠它回填前端聊天区。读 transcript（SQLite，最近 100 条），
#   不是 short_term（模型记忆窗口，20 条）

# memory/transcript.py —— 对话记录，只回填界面、不进提示词
SqliteTranscriptStore.append(session_id, user_text, assistant_text, *, channel="") -> None   # 写失败只告警不抛

                    on_thought=None, on_progress=None, on_delta=None, on_reasoning=None)

# prompts/loader.py
render_prompt(name: str, **variables: str) -> str      # 未提供的 {{占位符}} 渲染为空串；无 include/extends

# infra/agents_config.py

# infra/auth.py —— 宿主令牌与下载授权
issue_token(uid, *, name="", ttl_seconds=None, typ="id") -> str   # v1.<payload_b64>.<hmac_b64>
#   typ="id" / "dl" 用 AGENT_SHARED_SECRET（与宿主共享）；typ="adm" 用 ADMIN_TOKEN_SECRET（只在本服务）
verify_token(token, *, secret=None) -> Principal          # Principal.session_id == f"web:{uid}"

record_security_event(event, *, outcome="success", actor="", request=None, **fields) -> None

# tools/approvals.py —— 确认卡片登记簿（进程内，重启即清空）
ApprovalStore.request(session_id, tool_name, arguments, *, summary, rule_id, ..., chain="") -> PendingApproval
ApprovalStore.claim(task_id, operator) -> CardClaim          # 批准；reason 见 ClaimReason

ApprovalStore.complete(task_id, *, result_text, result_status, continuation) -> None

ApprovalStore.settle(task_id) -> None                        # 续跑结束，放开同一任务里后面的卡片
ApprovalStore.is_ready(task_id) -> bool                      # 网页：后面的卡片置灰

# skills/
```

`configs/profiles/<形态>/agent.md` 支持的占位符：`{{skill_index}}`（Skill L1 索引）、
`{{capability_notes}}`（按已挂载工具生成的能力备注）。没有其他动态变量。

### 确认卡片（策略 `challenge`）

**当前关闭**：`configs/policy.yaml` 的 `challenge_enabled: false`，`effect: challenge` 的规则一律按放行处理
（deny 照常生效），审计里该次调用的 `rule_id` 仍记下命中的确认规则，开启前可据此估算会弹多少卡片。
要开启改成 `true` 并重启，下面的流程才生效。

1. **出卡片**：工具调用命中 `configs/policy.yaml` 里 `effect: challenge` 的规则时不执行，登记一张卡片，
   模型只收到「已暂停，等用户确认」。卡片按**任务链**排先后：任务链 = 发起它的那一轮，批准后续跑那一轮
   出的卡片沿用原任务的链；同一会话里并行的不同任务互不阻挡。
2. **谁能点**：企微群卡片群成员都可以批准或拒绝（只限同一个群，点的人记进审计和卡片）；企微单聊卡片
   只认本人；网页卡片只认本会话。
3. **批准**：按登记时保存的参数执行一次，再把执行结果作为新一轮输入续跑原任务。续跑那一轮里按原参数
   再调同一工具，只回放已有结果、不重复执行（只限这条任务链；用户之后另起一轮要求再做一次，会重新出卡片）。
   执行失败也续跑，让模型解释原因，失败结果不回放。
4. **拒绝**：同样续跑一轮，告诉模型这项操作被拒、本轮不要再发起，把原任务里不依赖它的部分做完；
   这次拒绝不影响以后用户明确提出的新请求。
5. **先后顺序的呈现**：网页上同一任务里后面的卡片置灰，前面那张处理完自动变成可点（网页同一会话同时只
   跑一轮，执行完即放开）；企微卡片发出后改不了，所以一次只发能点的那张，卡片上注明「还有 N 项」，前一张
   的续跑结束后再推送下一张。越过顺序的点击服务端仍会拒绝（兜底）。
6. **有效期**：`DEFAULT_TTL_SECONDS`（10 分钟），卡片上显示具体的过期时刻；企微排队的卡片从发出时重新计时。
7. **渠道差异**：网页是「点批准 → `/api/chat/challenge` 执行 → 前端带 `resume_task_id` 调
   `/api/chat/stream` 续跑」两步；企微在卡片回调里直接执行、续跑，并主动推送回答、下一张卡片与文件。
   认领 / 作废 / 执行的规则两边共用 `channels/approval_flow.py`。

## 4. 配置权威源

改行为先改配置，不要改代码。

| 文件 | 管什么 |
|---|---|
| `configs/agent.yaml` | Agent 挂哪些 `tool_packs`（一份扁平列表） |
| `configs/tool_packs.yaml` | 工具包类路径、启用哪些工具、工具描述覆盖、pack 级 `config` |
| `configs/channels.yaml` | 通道启停：http_api（开）/ wecom（开，另需 `WECOM_ENABLED=true`）/ wechat（开，另需 `WECHAT_LINK_TOKEN`；`reply_mode` 等安全阀在它的 `config` 里） |
| `configs/base.yaml` | 护栏、记忆、压缩、对话记录、ReAct 循环、附件、工作区清理（含读路径放行前缀 `workspace.read_escape_prefixes`）、审计 |
| `configs/guardrail.yaml` | 护栏规则（输出规则同时作用于流式片段；`source: env_secrets` 规则启动时由已知密钥值生成） |
| `configs/profiles/<形态>/agent.md` | 各形态的系统提示词（`AGENT_PROFILE` 选择） |
| `configs/prompts/compactor.md` | Checkpoint 压缩器的系统提示词；缺失时回落 `compactor.py` 内置模板 |
| `configs/rules.md` | 持久规则与背景知识（类 CLAUDE.md），由 `main.py` 读入、经 `prompt_layout` 拼进 system 块 |
| `configs/domain_text.yaml` | 领域文案、空消息引导、附件提示、关键词→工具、实体提取 |
| `skills/fund-product-query/scripts/entities.yaml` | 结构化查询 QuerySpec 的实体/字段 Catalog（纯数据），由 `skills/fund-product-query/scripts/query.py` 经 `QueryCatalog.load()` 读取 |
| `.env`（见 `.env.example`） | 密钥、开关、超时、目录 |

`configs/` 下带 `_research` / `_legal` 后缀的文件是待机产品配置，加载器不认，

## 5. 工具清单

`configs/tool_packs.yaml` 定义 10 个工具包，`configs/agent.yaml` 当前挂载其中 4 个。

**已挂载**

| 工具包 | 工具 | 说明 |
|---|---|---|
| `script_executor` | `write_script` `run_script` | 脚本写入与执行。`run_shell` 已随 `shell_enabled: false` 下线，工具声明一并注释。子进程继承进程环境但剥掉名字像密钥的变量（KEY/SECRET/TOKEN/PASSWORD…）；`env_extra` 声明的变量**只注入给 Skill 自带脚本**（凭证只能放这里），`env_extra_all` 所有脚本可见（只放路径、开关）。`run_script` 命中 `<skill:name>/scripts/x.py` 时走只读的 Skill 目录解析，不受 `scripts_dir` / 会话隔离限制，`cwd` 为脚本所在目录。`run_script` 失败（退出码非 0、超时、路径被拒）抛 `ToolCallError`，审计里记 `status=error`；失败文本报错在最前（首行带异常行，traceback 去掉 runner / runpy 栈帧，stderr 只留结尾 2000 字），出错前的 stdout 附在后面。**product 形态**覆盖为 `write_enabled: false` + `skill_scripts_only: true`：不挂 `write_script`，`run_script` 只认 Skill 脚本 |

## 6. Skill 系统

`skills/{name}/SKILL.md`（frontmatter + 正文 + 可选 `scripts/` `references/` `assets/`）
经 `SkillDiscovery` 扫描，三级渐进式披露：

- **L1** 索引常驻 system prompt（`render_index()`）
- **L2** 模型调 `load_skill(name)` 拿正文与资源清单
- **L3** 模型用 `read_file` / `run_script` 主动读资源

形态 `profile.yaml` 的 `resident_skills` 把 L2 也常驻：这些 Skill 的正文、资源清单与声明工具每轮放在
system prompt 末尾（`render_resident_skills()`），索引里标「已常驻」，`load_skill` 对它们只回一句提示。
只能写本形态 `skills` 白名单里的名字。硬约束模式下常驻 Skill 的资源视同已加载，但它的 `allowed-tools`
不在每轮开头生效。research 形态常驻 `fund-research-db`（2026-10-22 审计：每个问题都要先花一轮
`load_skill`，跨轮也不保留正文）。

`allowed-tools` 可把该 Skill 的工具集设为会话级硬约束（`configs/tool_packs.yaml` 的
`skills.config.enforce_allowed_tools: true` 时，越界调用被 `ToolRegistry` 拦截）。

`<skill:name>/rel_path` 路径前缀由 `tools/skill_paths.py` 唯一解析，`read_file` 与
`run_script` 共用。

Skill 还可以声明两样东西（都可选）：根目录的 `tools.yaml`（原生工具，见 §5 末尾），以及 frontmatter 的
`python-path`（Skill 内的目录列表，run_script 把它们放进子进程 PYTHONPATH，会话脚本可以直接
`from lib import …`；多个 Skill 有同名模块时按 Skill 名排序先到先得）。

规范见 `skills/README.md`。
进程内热重载走 `POST /api/skills/reload`。

## 7. 约束

**架构**

- 不引入多 Agent 编排 / dispatch / intent router，也不引入按业务场景切配置的模式开关。
  一个进程一个 Agent、一份 `configs/agent.yaml`。
- 不引入 LangChain / LlamaIndex 等重框架，ReAct 循环自持。
- 新能力优先级：**Skill 文档 > 改配置 > 新工具包 > 改核心循环**。
  改 `react/loop.py` / `agent.py` 是最后手段。
- 知识 / 账户 / 交易能力未移植，需要时走 `http_call` 或 MCP，不新建网关 pack。

**工具**

- 工具必须继承 `BaseTool`，经 `ToolPack` 注册、在 `tool_packs.yaml` 声明；禁止在 Agent 里硬编码工具实例。
- `execute()` 返回值必须是 `str`。超过 `react.max_tool_result_chars` 时循环侧先外置再回灌占位；外置失败才硬截断。
- 有结构化参数的工具覆盖 `parameters_schema` property。
- 任何文件路径必须经工作区解析函数，禁止裸 `open()` / 裸 `subprocess`。
- 工具执行失败返回可读错误文本，不要抛异常穿透。
- `ToolRegistry` 按工具名去重，两个 pack 不能产出同名工具。

**安全边界**（必须由代码兜住，不能只写进提示词）

- 读类工具（列目录、读文件、发文件、搜索）对「能看见什么」只能有一个口径：`tools/visibility.py`。
  新增读类工具必须过 `bind_session_workspace_path` 或 `is_visible_to_session`。
- 脚本要用的凭证只能放 `env_extra`（只给 Skill 自带脚本）；`env_extra_all` 对模型现写的脚本也可见，只放非敏感值。
- 流式出站的文本（正文、思考过程）必须先过 `OutputGuard.stream()`；全文 `review()` 只用于落库与审计，不能把结果再追加给客户端。
- 越过普通用户权限的动作（管理操作、签令牌、凭授权下载）调 `record_security_event` 留痕；令牌、口令、密钥本身不进事件。
- 管理令牌只用 `ADMIN_TOKEN_SECRET` 签，任何给宿主的密钥都不能签出本服务的管理权限。

**配置**

- 配置文件只放真正会按部署环境变化的值。禁止 `xxx: ""  # 空则回落 settings.xxx` 这种两处维护同一默认值的写法。
- 敏感值（token / key）走 `.env` / `Settings`，不进任何提交到仓库的 YAML。

**其他**

- 提示词正文放 `configs/profiles/<形态>/agent.md`；Python 里只做占位符填充。
  业务 SOP、业务身份陈述进 Skill，不进 system prompt。
- 记忆 / 审计 / 护栏统一由 `agent.py` 串，工具和 Skill 不自己写审计。
- 遵守项目注释规范：文件头注释、函数 docstring、分节分隔注释。
- 新增能力要带测试；删代码时同步删掉对应的测试 / 配置 / 文档引用。

## 8. 扩展操作手册

**加一个工具包**

1. `src/csagent/tools/packs/<name>_pack.py`：`BaseTool` 子类（覆盖 `parameters_schema`）+ `ToolPack` 子类
2. `configs/tool_packs.yaml` 增加条目（`pack_class` / `tools` / `description`；`config` 只在真有环境相关参数时才加）
3. `configs/agent.yaml` 的 `tool_packs` 列表加上包名
4. 需要的话在 `prompts/capability_notes.py` 加一条能力备注
5. `tests/test_<name>_pack.py` 覆盖正常路径 + 越权路径

**加一个 Skill**

1. `skills/<skill-name>/SKILL.md`，目录名 = frontmatter 的 `name`，kebab-case
2. frontmatter 必填 `name` / `description`（>=20 字符）；可选 `version` / `tags` / `allowed-tools` / `enabled`
3. 脚本与资料放 `scripts/` / `references/` / `assets/`，正文用 `` `<skill:name>/scripts/x.py` `` 引用
4. 对照 `skills/README.md` 看 frontmatter 和资源路径是否齐全

**加一个业务场景**

给唯一的 Agent 多挂一项能力，不是加 Agent。默认路径是 Skill 脚本，不是新 ToolPack。
照抄 `fund-product-query` 的文件结构：

1. 数据 / 能力层写成 Skill 自带脚本（薄 CLI，`argparse` 的 action/payload），
   模型用已挂载的 `run_script` 调用，通常不需要改 `tool_packs.yaml`。
   **代码放哪里按「认不认识具体 entity/字段名」分**：只做 Catalog 数据驱动的通用校验、
   不认识任何具体业务名词的部分（对照 `catalog.py` / `executor.py` / `models.py` / `schema.py`）
   留在 `src/csagent/tools/semantic/`，用 `import csagent.xxx` 复用；按具体 entity / 字段名
   分发请求、做业务转换的 backend 代码写成 Skill 自己 `scripts/` 下的同目录模块，
   互相用 `from xxx import yyy` 而不是 `csagent.` 包路径（`python script.py` 会把脚本目录
   放进 `sys.path[0]`）。
2. 业务规则、业务身份 / 边界陈述写进 SKILL.md 正文，不进 system prompt。
   正文要写清调用约定（脚本路径 + 参数形状），因为没有 JSON Schema 兜底。
3. 只有当这项能力确实需要一个配置不同的脚本执行实例时，才在 `configs/tool_packs.yaml`
   新增 pack 实例，并把包名加进 `configs/agent.yaml`。
4. 跨场景通用的能力（如 `reply_preference`）单独成包。
5. 脚本测试用 `importlib.util.spec_from_file_location` 直接加载，参考
   `tests/test_fund_product_query_script.py`；`tests/conftest.py` 已把
   `skills/fund-product-query/scripts/` 加进 `sys.path`。
6. 起服务实测一遍。脚本路径这层没有 Schema 兜底，只跑单测不够。

**加一个通道**

1. 实现 `channels/base.py` 的通道协议
2. `configs/channels.yaml` 注册，`manager.py` 自动启停
