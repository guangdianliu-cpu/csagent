# 宿主接入说明

面向对接方（宿主产品）研发，前后端都看这一篇。

智能体小窗跑在最终用户的浏览器里，以 iframe 嵌进宿主产品，登录态经 `postMessage` 下发，不走 URL。
宿主后端用共享密钥为每个已登录用户签发短时效令牌，智能体服务用同一把密钥验签；
密钥不出宿主服务端，浏览器只拿得到令牌。会话历史、文件、回复偏好都挂在 `session_id = web:{uid}` 上，
`uid` 来自验签结果。

- 智能体页面：`https://{智能体域名}/`
- 接入 SDK：`https://{智能体域名}/csagent/agent-widget.js`

---

## 一、对接方要做的事

1. **保管共享密钥**（§二.1）
2. **后端加签发接口**，按 §二.2 的格式签令牌
3. **前端接 SDK**，把令牌交给小窗并定时续期（§三）
4. **提供域名**，我们加进 origin 白名单（§七.1）

---

## 二、令牌签发（后端）

### 1. 共享密钥

密钥通过安全渠道（当面 / 密码管理器 / 加密邮件）单独提供，不走微信和邮件正文。

- 放进服务端配置（配置中心 / 环境变量 / KMS），不进 Git，不下发前端
- 长度至少 32 字符，两边必须完全一致
- 泄露或人员变动时通知我们轮换

智能体侧对应 `.env` 的 `AGENT_SHARED_SECRET`。未配置或长度不足 32 会直接抛错，不会静默放行。

### 2. 签发接口

给自己的前端用，路径自定，例如 `GET /api/agent/token`：用现有登录态确认当前用户
→ 用共享密钥签令牌 → 返回给前端。

**令牌格式**

```
v1.<base64url(payload的JSON)>.<base64url(HMAC-SHA256签名)>
```

- base64url 用 URL 安全字母表（`-` `_`），去掉结尾的 `=` 补位符
- 签名输入是 `v1.<payload的base64url>` 整串，含 `v1.` 前缀
- 算法固定 HMAC-SHA256，令牌里不写算法字段

**payload 字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| `uid` | 是 | 宿主系统里稳定不变的用户主键。会话记忆按它隔离 |
| `exp` | 是 | 过期时间，Unix 秒。建议 `当前时间 + 1800` |
| `iat` | 否 | 签发时间，Unix 秒 |
| `name` | 否 | 展示名，仅用于界面显示 |

`uid` 用工号 / 用户 ID 这类不会变的值，不要用手机号、邮箱或姓名；数字转成字符串即可。

**Java 参考实现**

```java
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.util.Base64;

public class AgentToken {

    private static final String SECRET = /* 从配置读取，不要硬编码 */ "";
    private static final Base64.Encoder B64 = Base64.getUrlEncoder().withoutPadding();

    public static String issue(String uid, String name, long ttlSeconds) throws Exception {
        long now = System.currentTimeMillis() / 1000;
        // 字段顺序不影响验签，但 JSON 必须是紧凑格式
        String payload = String.format(
            "{\"uid\":\"%s\",\"iat\":%d,\"exp\":%d,\"name\":\"%s\"}",
            uid, now, now + ttlSeconds, name);

        String body = B64.encodeToString(payload.getBytes(StandardCharsets.UTF_8));
        String signingInput = "v1." + body;

        Mac mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(SECRET.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
        String sig = B64.encodeToString(
            mac.doFinal(signingInput.getBytes(StandardCharsets.US_ASCII)));

        return signingInput + "." + sig;
    }
}
```

生产代码用 Jackson/Gson 生成 JSON，不要拼字符串：`name` 里有引号或反斜杠会把 payload 拼坏。

**自测向量**

密钥 `test-secret-that-is-long-enough-for-hmac-32`：

```
payload（紧凑 JSON，键之间无空格）:
{"uid":"u1001","iat":1767225600,"exp":4070908800}

期望完整令牌:
v1.eyJ1aWQiOiJ1MTAwMSIsImlhdCI6MTc2NzIyNTYwMCwiZXhwIjo0MDcwOTA4ODAwfQ.afTcUNV5pu_yc890pWj1-IrXtJnGzDb85eweO_dY4LA
```

该向量的 `exp` 是 2099 年，可直接打测试环境验证整条链路。签名对不上最常见的三个原因：
base64 用了标准字母表而非 URL 安全的、没去掉 `=` 补位、签名时漏了 `v1.` 前缀。

## 三、前端嵌入（SDK）

对接方不需要拷贝任何页面。气泡、弹窗、iframe、握手都封装在 `agent-widget.js` 里：

```html
<script src="https://{智能体域名}/csagent/agent-widget.js"></script>
<script>
  CsAgentWidget.init({
    origin: 'https://{智能体域名}',
    getAuth: function () {
      return {
        userId:   currentUser.id,         // 必填，要和令牌里的 uid 一致
        userName: currentUser.name,
        token:    currentUser.agentToken  // 必填，§二.2 签发的令牌
      };
    },
    onMessage: function (msg) {
      if (msg.type === 'unauthorized') {
        refreshMyToken().then(() => CsAgentWidget.refreshAuth());
      }
    }
  });
</script>
```

放在宿主产品的全局布局 / 主框架里（每个页面都要有小窗），或某个页面组件里
（只在特定页面出现）。SPA 项目可把 `agent-widget.js` 放进自己的静态资源用 `import` 引入。

### 令牌续期

令牌默认 30 分钟过期（`AGENT_TOKEN_TTL_SECONDS`）。宿主前端起一个比有效期短一些的定时器
（例如 25 分钟）重新取令牌，然后调 `CsAgentWidget.refreshAuth()`：重新调 `getAuth()` 下发新令牌，
不打断正在进行的对话。小窗每次被打开时也会重新调一次 `getAuth()`；令牌失效时发 `unauthorized`
（见上例）。

### API

| 方法 | 用途 |
|---|---|
| `CsAgentWidget.init(options)` | 初始化，创建气泡与弹窗 |
| `CsAgentWidget.open()` / `.close()` | 手动开合 |
| `CsAgentWidget.refreshAuth()` | 切账号或 token 续期后必须调用 |
| `CsAgentWidget.logout()` | 登出，锁住小窗 |
| `CsAgentWidget.isBusy()` | 是否正在生成回复 |
| `CsAgentWidget.resetPosition()` | 回到右下角默认位置与尺寸 |

### 可选配置

`title` / `width` / `height` / `position`（`right`\|`left`）/ `themeColor` /
`zIndex` / `openOnInit` / `confirmCloseWhenBusy` / `onBusyChange` / `onMessage` / `debug` /
`draggable`（默认 true）/ `resizable`（默认 true）

### 拖动与缩放

- 拖动：按住小窗标题栏。`draggable: false` 关闭
- 缩放：八个方向的边角可拉，最小 `320 × 380`。`resizable: false` 关闭
- 位置与尺寸记在 `localStorage`（`csagent_widget_geom`）
- 拖出屏幕后调 `resetPosition()` 复位

拖拽需要内外配合：指针移到 iframe 上时宿主文档收不到 `mousemove`，所以标题栏的
`mousedown` 由小窗侧发 `drag-start` 消息给宿主，宿主接管后盖一层全屏透明遮罩接事件。
自己实现 UI 的宿主要处理这条消息。

### 样式与尺寸

- 建议 `400 × 600`，最窄适配到 `360px`
- 页面自带深色标题栏（含关闭按钮），宿主不需要再画一层头部
- `≤460px` 时自动压缩间距、缩小表格字号、限制思考区高度

## 四、底层 postMessage 协议

用 SDK 时不需要看这一节，宿主自己实现 UI 时才需要。

### 握手

```
宿主                                    智能体小窗
 │                                          │
 │  ← { source:'csagent-widget',            │  iframe 加载完成后主动发出
 │      type:'ready' }                      │
 │                                          │
 │  → { source:'csagent-host',              │
 │      type:'auth', payload:{...} }        │
 │                                          │  建立会话，放行输入框
```

必须等收到 `ready` 再下发 `auth`：iframe 未加载完时 postMessage 会丢。

### 宿主 → 小窗

统一形如 `{ source: 'csagent-host', type, payload }`。

**`auth`** — 下发 / 刷新登录态

| 字段 | 必填 | 说明 |
|---|:--:|---|
| `userId` | **是** | 决定会话与记忆边界，见 §五。缺失会被拒绝 |
| `userName` | 否 | 仅用于小窗标题栏展示 |
| `token` | **是** | 宿主签发的令牌，小窗放进 `Authorization: Bearer` 请求头 |
| `title` | 否 | 覆盖小窗标题 |

可重复下发：token 续期直接再发一次，不打断正在进行的对话。
若 `userId` 与上次不同，视为切账号，小窗清空聊天区并切换到新会话。

**`logout`** — 小窗立即锁定输入并显示重新登录提示。`payload` 可为空。

**`ping`** — 存活探测，小窗回 `pong`。

### 小窗 → 宿主

统一形如 `{ source: 'csagent-widget', type, payload }`。

| type | 时机 | payload | 宿主该做什么 |
|---|---|---|---|
| `ready` | iframe 加载完成 | `{version, wants}` | 下发 `auth` |
| `close` | 用户点了标题栏 × | `{}` | 收起弹窗 |
| `busy` | 开始/结束生成回复 | `{busy: bool}` | 可据此拦截关窗，或在气泡上打未读点 |
| `drag-start` | 用户按住标题栏 | `{x, y}` 按下点在小窗内的坐标 | 接管拖动：盖全屏遮罩接 `mousemove`，按 `(鼠标 − xy)` 定位面板 |
| `unauthorized` | 令牌失效 | `{}` | 续期后调 `refreshAuth()` |
| `pong` | 收到 `ping` | `{}` | — |

## 五、会话与记忆边界

`session_id` 由服务端从验签后的令牌派生，**不接受客户端传入**（请求体里没有这个字段）：

```
session_id = "web:" + uid
```

与企微侧 `wecom:{from_user}` 口径一致。按用户长期连续：关窗、换浏览器、隔天再来，
上下文历史、会话快照、回复风格偏好都还在。

由此产生两条约束：

1. `userId` / `uid` 必须是稳定的用户主键，不能用会话 id、不能每次登录都变
2. 切账号必须重新下发 `auth`，否则小窗会继续用旧 `userId`

需要「每个研究项目一条独立会话」时，改成 `web:{uid}:{conversationId}` 并由宿主传
`conversationId`。

### 刷新页面后的聊天记录

小窗拿到 `auth` 后调一次 `GET /api/chat/history`，把服务端最近 100 条
（约 50 轮问答，`transcript.max_return`）放回聊天区，末尾用一条「以上为历史消息」分隔。
宿主不需要做任何事，重复下发 `auth` 也只回填一次。

记录落在服务端 SQLite（`data/transcripts.db`）：

- 服务重启不丢，换浏览器、换电脑也在（跟着 `uid` 走，不是本地缓存）
- 默认保留 30 天，启动时清理更早的（`transcript.retention_days`）
- 浏览器侧不另存 localStorage 副本

**界面能翻到的 ≠ 模型还记得的**。模型的记忆窗口默认 20 条，更早的压成 Checkpoint 摘要。

## 六、接口契约

小窗自己会带令牌，正常情况下宿主不需要直接调这些接口。

| 接口 | 鉴权 | 说明 |
|---|---|---|
| `POST /api/chat/stream` | `Authorization: Bearer <令牌>` | SSE 流式聊天；同一会话已有一轮在跑时返回 409 |
| `POST /api/chat/stop` | 同上 | 终止本会话正在跑的一轮（含关页后仍在后台跑的），幂等；被停的流收到 `stopped` 事件 |
| `GET /api/chat/history` | 同上 | 回填聊天区，最近 100 条 |
| `POST /api/files/upload` | 同上 | 上传附件 |
| `GET /api/files/download` | 令牌，或链接自带的 `dl` 授权 | 下载 |
| `GET /api/skills` | 同上 | 能力清单 |
| `POST /api/skills/reload` | 管理员令牌 | 热重载 Skill，运维动作；宿主令牌调不了 |
| `GET /api/chat/config` | 不需要 | 只返回两个开关，无用户数据 |
| `POST /api/auth/dev-token` | 无 | 仅 `AGENT_AUTH_DEV_LOGIN=true` 时存在，否则 404 |
| `/admin`、`/api/admin/*` | 管理员账号登录（`ADMIN_ACCOUNTS`） | 数据管理后台，与宿主令牌互不通用，见 `docs/数据管理后台.md`。管理令牌用本服务独有的 `ADMIN_TOKEN_SECRET` 签名，与共享密钥无关——对接方持有的共享密钥签不出管理令牌 |

令牌取自 `Authorization: Bearer`，兼容 `X-Host-Token` 头。

**下载授权**：企微通道的下载链接自带一个路径级签名（`typ="dl"`），只对签发时那一个
workspace 路径有效，不含身份，换不到其他接口的访问权，TTL 由
`AGENT_DOWNLOAD_GRANT_TTL_SECONDS` 独立控制。授权只能指向会话目录与已启用 Skill 的资源，
指向记忆库、审计日志、配置等路径的授权一律 403；每次凭授权下载都记安全审计。

**返回码**

| 码 | 含义 | 排查方向 |
|---|---|---|
| 401 | 令牌缺失、签名不对、已过期 | 密钥是否一致、`exp` 是否是秒（不是毫秒）、签名输入是否含 `v1.` 前缀 |
| 403 | 敏感文件，或下载链接与目标不符 | 正常拦截 |
| 404 | 文件不存在，或不属于当前用户 | 两种情况不区分 |
| 503 | HTTP 通道被关闭 | 联系我们 |

401 不区分「签名错」与「已过期」，具体原因在服务端日志里。

## 七、上生产前的检查项

### 1. origin 白名单

智能体只接受白名单内 origin 下发的身份，配置在 `static/index.html` 的 `HOST_ORIGIN_ALLOWLIST`。当前值：

```js
const HOST_ORIGIN_ALLOWLIST = [
  "https://lab.leadfund.com.cn",       // 生产：宿主产品
];
```

留空时接受任意页面下发的身份，控制台会持续告警。新增环境由对接方提供域名，加进这个数组。

宿主侧同样要校验：

```js
if (e.origin !== 'https://{智能体域名}') return;
```

### 2. framing 头

服务端不设置任何 framing 头，默认可被任意站点 iframe。生产应在反向代理或应用层加：

```
Content-Security-Policy: frame-ancestors https://lab.leadfund.com.cn
```

不要加 `X-Frame-Options: SAMEORIGIN`，那会把宿主的 iframe 一起挡掉。
若生产 Nginx 有统一安全头模板，确认它没有默认下发 `X-Frame-Options: DENY`。

### 3. 网络开放范围

智能体服务默认监听 `8000`（`APP_PORT`）。建议只对内网 / 宿主服务器开放。
必须出公网时建议再加一层 IP 白名单或 WAF。

### 4. 鉴权开关

| 环境变量 | 默认 | 生产取值 / 说明 |
|---|---|---|
| `AGENT_SHARED_SECRET` | 空 | 必配，至少 32 字符，与测试环境不同 |
| `AGENT_AUTH_ENABLED` | `true` | 必须 `true`。`false` 时退化为匿名身份（仅本地开发），`session_id` 仍由服务端派生 |
| `AGENT_TOKEN_TTL_SECONDS` | `1800` | 令牌有效期 |
| `AGENT_AUTH_DEV_LOGIN` | `false` | **必须 `false`**。开启后 `/api/auth/dev-token` 可为任意 uid 换令牌 |
| `AGENT_DOWNLOAD_GRANT_TTL_SECONDS` | 见 `.env.example` | 下载授权有效期 |

### 5. 内网无外网时

页面引用两个 CDN 脚本（`marked` / `DOMPurify`）用于 Markdown 渲染，已改为 async 加载，
取不到不阻塞首屏，自动回退到内置渲染器（支持标题、粗斜体、代码块、列表、表格、链接）。
要完全去掉外网依赖，把这两个库下载到 `static/assets/` 并改成本地引用。

## 八、联调与自测

### 联调步骤

1. 我们提供测试环境地址和测试用密钥（与生产不同）
2. 对接方实现签发接口，用 §二.2 的自测向量确认签名算法正确
3. 在测试页面接入 widget，打开小窗能正常对话即联调通过
4. 换生产密钥、提供生产域名、过一遍 §七，上线

联调期测试环境可开 `AGENT_AUTH_DEV_LOGIN=true`，签发接口还没写好时先跑通前端嵌入：

```bash
curl -X POST https://{测试环境}/api/auth/dev-token \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"u1001","name":"测试用户"}'
```

### 不依赖宿主的自测

直接用浏览器打开智能体页面即进入 mock 登录态（右上角有橙色 `MOCK 登录态` 角标）：

- `http://localhost:8000/` — 默认 mock 用户 `u1001`
- `http://localhost:8000/?userId=u2001&userName=张三` — 指定 mock 身份
- 页面底部有调试身份栏，改「用户 ID」可切换 mock 用户，验证记忆是否按用户隔离

嵌入状态下想强制走 mock，在 iframe src 上加 `?mock=1`。

## 九、常见问题

**能不能用固定的 API Key？**

不能。小窗跑在最终用户浏览器里，key 会下发到每个用户。且 key 只能证明请求来自宿主系统，
证明不了具体是谁，不解决越权问题。

若宿主愿意做服务端反代（浏览器 → 宿主后端 → 智能体服务），API Key 模式成立，
但需要宿主后端能透传 SSE 流。这是另一套方案，需要单独沟通。

**令牌有效期能设成 7 天吗？**

不建议。30 分钟 + `refreshAuth()` 续期的体验与 7 天相同，泄露后的攻击窗口小两个数量级。

**能查用户在智能体侧的历史吗？**

目前没有开放查询接口。需要的话要单独设计管理员鉴权。
