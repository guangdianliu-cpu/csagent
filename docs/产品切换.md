# 产品切换（部署形态）

仓库远端：内网 GitLab `origin`（`git@10.1.1.90:root/cs-agent.git`）。

---

## 一、机制

**形态只由一个变量决定：`AGENT_PROFILE`。切换不改任何文件，工作区始终干净。**

| 内容 | 位置 | 入库 |
|---|---|---|
| 系统提示词 | `configs/profiles/<形态>/agent.md` | 是 |
| 工具包、工具配置覆盖、领域文案覆盖、**Skill 白名单** | `configs/profiles/<形态>/profile.yaml` | 是 |
| 公共配置（LLM、鉴权密钥等） | `.env` | 否 |
| 实例配置（企微机器人、端口、偏好目录） | `.env.<形态>`，覆盖 `.env` 同名项 | 否 |

`AGENT_PROFILE` 取值顺序：进程环境变量 > `.env` > `configs/agent.yaml` 的 `default_profile`（当前为 `product`）。

现有形态：

| 形态 | 目录 | 可见 Skill | 常驻 Skill |
|---|---|---|---|
| 投研 | `configs/profiles/research/` | `fund-research-db` | `fund-research-db` |
| 产品咨询 | `configs/profiles/product/` | `fund-product-query` | （无） |

- 形态写了 `skills:` 白名单时，以白名单为准，`SKILL.md` 里的 `enabled:` 不再起作用；不用再改 `SKILL.md`。
- `resident_skills:` 列出的 Skill 说明每轮直接放在系统提示词末尾，模型不用每个问题先 `load_skill`
  （几乎每问都要用的 Skill 才值得常驻，正文每轮都占上下文）。只能写 `skills:` 白名单里的名字，
  写错启动时报 `resident_skill_unavailable`。
- 形态没写的工具包 / 领域文案沿用 `configs/agent.yaml`、`tool_packs.yaml`、`domain_text.yaml`。
- 其它提示词（如 `compactor.md`）也可以在形态目录里放同名文件覆盖 `configs/prompts/` 的版本。

## 二、首次配置

在项目根按形态建实例配置（不入库，`.gitignore` 已忽略 `.env.*`）：

```ini
# .env.research
WECOM_BOT_ID=...
WECOM_SECRET=...
APP_PORT=8001
REPLY_PREFERENCE_DIR=/usr/local/leadsys/csagent-preference/research
```

```ini
# .env.product
WECOM_BOT_ID=...
WECOM_SECRET=...
APP_PORT=8000
REPLY_PREFERENCE_DIR=/usr/local/leadsys/csagent-preference
```

机器人密钥**只放这里**，不要写进任何入库文件。

---

## 三、启动与查看

```bash
AGENT_PROFILE=research python -m csagent.main
AGENT_PROFILE=product python -m csagent.main
```

Windows：`$env:AGENT_PROFILE="research"; python -m csagent.main`。不设 `AGENT_PROFILE` 时用 `.env` 里的值，没有则用默认形态。

切形态 = 停进程 → 换形态启动。改了提示词 / profile 同样需要重启。

---

## 四、新增一个形态

1. 建目录 `configs/profiles/<新形态>/`，放 `agent.md` 和 `profile.yaml`（写上 `skills:` 白名单）。
2. 领域文案有差异的键写进 `profile.yaml` 的 `domain_text:` 段（必需键见 `csagent/prompts/domain_text.py` 的 `REQUIRED_KEYS`）。
3. 需要时建 `.env.<新形态>`。
4. `AGENT_PROFILE=<新形态> python -m csagent.main` 启动。

本地私有形态（不入库）：把目录加进 `.gitignore` 即可，例如 `configs/profiles/legal/`。
旧的平铺文件 `configs/profiles/<形态>.yaml` 仍兼容读取。

---

## 五、从旧切换方式迁移

旧方式靠给 `agent.md` / `agent_research.md` 改名、改 `SKILL.md` 的 `enabled:`、改写 `.env`。迁移步骤：

1. `git pull` 之前，如果工作区是「投研转正」状态（改过名的文件），先 `git stash` 或 `git checkout .` 还原。
2. 按第二节建 `.env.research` / `.env.product`，机器人密钥只放这里。
3. `.env` 里原有的 `WECOM_BOT_ID` / `WECOM_SECRET` / `APP_PORT` / `REPLY_PREFERENCE_DIR` 可以删掉（留着也会被 `.env.<形态>` 覆盖）。

> 旧启动脚本曾把两个企微机器人的 secret 明文提交进仓库，git 历史里仍可查到，
> **请在企微后台重置这两个 secret**，新值只写进 `.env.<形态>`。

---

## 六、同机同时跑两套

两套进程用不同端口和不同机器人即可共存。但 `data/` 下的记忆库、审计、上传目录按项目目录划分，
**同一个目录同时跑两套会共用这些数据**。需要同时跑时，仍按原做法用两个独立目录部署
（例如 `/home/product`、`/home/research`），各自设 `AGENT_PROFILE`。
