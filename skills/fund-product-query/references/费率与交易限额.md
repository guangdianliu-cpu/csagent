## 费率与交易限额

### 适用场景
- 申购费率？/ 手续费多少？/ 赎回费？
- 起购多少？/ 追加多少？/ 单日限额？/ 最多能买多少？
- 申购确认几天？/ 赎回到账？

### 查询指引
- **优先** `product_lookup`（单只也可以）：aspects 含 `basic`/`limits`/`fees`/`discounts`
  - 默认 `custtype=0`（机构）；用户明确问个人时再传 `1`
- 降级：`product_entity_query` 查 `fund_fee_rates` / `fund_rate_discounts` / `fund_trade_limits`（仅 product_lookup 不可用时）
- 分档申赎费率字段：
  - `faretype`：认购费 / 申购费 / 赎回费
  - `flag`/`flag_name`：`费率`（看 `fareratio`%）或 `单笔`（看 `farevalue` 元/笔）
  - 金额档用 `minvalue`/`maxvalue`（元）；赎回持有期档同样用这两列（天）
- 折扣：默认陈述 `discount_desc` / `fix_discount_desc` 原文，勿自行用 0/1/0.1 反推。
  **例外**：会话上下文里的输出模板明确要求「折后费率」时，按 `原费率 × discount` 换算（`discount` 是数值字段，如 0.0178；不是 `discount_desc` 文本），结果保留 3 位小数
- **折扣按业务分行，先认 `busincode_name` 再落到对应费用上**：一行折扣只对该业务生效
  （`busincode` `020`=认购 / `022`=申购 / `024`=赎回；`busincode_name` 已给出中文名，其余业务码显示为「其他业务(xxx)」）。
  同一只基金**认购折扣与申购折扣经常不一样**（如认购 1 折、申购 0.1 折），照行取用，**禁止跨业务套用或凭印象对号入座**；
  未知业务码如实说明是哪项业务未明，不要硬塞进申购/认购
- **费率折扣与单笔固定费用折扣是两个独立因子，禁止混用**（见每行的 `discount_scope`）：
  - `discount` → 只打**费率档**（`fees` 里 `flag=0`，按 `fareratio`%）
  - `fix_discount` → 只打**单笔固定费用档**（`flag=1`，按 `farevalue` 元/笔）
  - 业务上允许两者取值不同，最常见的就是**费率打折、单笔固定费用不打折**（`fix_discount=1` → `fix_discount_desc`「不打折（按原费率）」）。
    此时该档仍按原 `farevalue` 元/笔收取，**不得把 `discount` 的折扣套到单笔档上**（例：申购费率档 0.1 折，但 ≥500 万那档 1000 元/笔照收不打折）
- 管理费 / 托管费 / 销售服务费：看 basic 里的 `manage_ratio` / `hosting_rate` / `service_rate`（%/年）
- 确认与交收（basic）：
  - `buy_ack_days` → 申购确认 T+N
  - `redeem_ack_days` → 赎回份额确认节点（勿与到账相加，也勿说成到账）
  - `redemption_cash_date` → 赎回到账总周期（对客「几天到账」只认此字段）
- 用户问「怎么算的」：说来自上述工具字段，禁止编造算错/混字段的自我归因；前后不一致以最新工具结果为准
- `maxvalue` / `day_max_sum` / `max_value` **≥ 9999999999** → 「暂无明确上限」

### 业务规则
- 按本次查询的客户类型作答并标注；未指定身份默认机构，勿擅自双报
- 折扣未返回时不臆造；不承诺客户实际成交费率
- 费率按金额档陈述；不确定档位就列出查到的档
- 不做「推荐买多少」的投资建议；答完即止，禁止引导话术

### 回复要点
- 说明业务（申购/赎回）、客户类型、档位与数字；单笔档必须带 `farevalue`
- 有折扣写清折扣说明，并写明**是哪项业务的折扣**（认购/申购/赎回，取自 `busincode_name`）；
  费率档与单笔固定费用档分开写，单笔档不打折时明确写「单笔固定费用不打折，仍按 X 元/笔」
- 管理/托管/销服费有值则报年费率
- 无上限用「暂无明确上限」；缺数据如实说暂未配置

### 边界
- 不编造折扣或临时优惠；不臆造未返回的确认日/到账天数
